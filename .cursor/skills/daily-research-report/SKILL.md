# 日次リサーチレポート

毎営業日、寄り付き前に5分で終わる確認手順。目的は「今日の推奨を読む」ことではなく、
**今日の推奨を信用してよいかを判定すること**。順序を守る。データの状態を見る前に推奨を読むと、
古いデータに基づく推奨を鵜呑みにする。

関連仕様: [08-agent-loop.md](../../../docs/08-agent-loop.md)、
[11-security-ops.md](../../../docs/11-security-ops.md) §7、
[ui/screens/01-dashboard.md](../../../docs/ui/screens/01-dashboard.md)

## 朝の手順（寄り付き前、目安5分）

### 1. バッチの成否（最優先）

`/` のダッシュボード上部、または:

```bash
curl -s localhost:8000/api/v1/agent/jobs?limit=6 | jq -r \
  '.data[] | "\(.job_name)\t\(.status)\t\(.finished_at)\t\(.output_summary_ja)"'
```

| 状態 | 判断 |
| --- | --- |
| 6ジョブすべて `success` | 次へ |
| いずれかが `partial` | 何が欠けたかを確認し、下の「部分失敗の判断表」に従う |
| いずれかが `failed` | 推奨を読む前に原因を確認。多くの場合その日の推奨は信用できない |
| `interrupted` のまま | 再起動で中断し、自動再開もされていない。手動で再実行 |
| ジョブが存在しない | スケジューラが動いていない。`systemctl --user status ai-stock-agent` |

### 2. データ鮮度

```bash
curl -s localhost:8000/api/v1/system/freshness | jq -r \
  '.data[] | "\(.source)\t\(.status)\t\(.latest_as_of)"'
```

確認するのは以下2点だけ。

- `yfinance_jp` / `yfinance_us` が当日または直近営業日か（参考現在値が古いと参考価格が危険）
- `edinet` が当日分まで来ているか（前日15時以降の開示が反映されているか）

`jquants` が3ヶ月前を指しているのは**正常**。無料プランの12週遅延によるもので、異常ではない。
ここを毎回異常と誤認しないこと。

### 3. LLMコスト

```bash
curl -s 'localhost:8000/api/v1/agent/cost?period=daily&days=1' | jq '.data'
```

- 当日の消費が上限の80%を超えていたら、その日の残りの手動要約は控える
- キルスイッチが有効になっていたら、その日の推奨は定性評価を含まない
- 当月見込みが月次上限を超えそうなら、対象ユニバースを絞る

### 4. 推奨の確認

`/recommendations` を開く。**カードごとに以下の順で読む**。

1. **弱気論拠を先に読む**。強気論拠から読むと確証バイアスがかかる
2. 期待超過リターンの**区間の幅**を見る。点推定は見ない
3. 的中率の**母数（n）**を見る。n < 20 なら参考程度に扱う
4. 警告系の reason code（`DATA_STALE`、`MODEL_LOW_CONFIDENCE`、`EVENT_EARNINGS_SOON`）を確認
5. 引用の検証ステータスが `検証済み` になっているか
6. レビュー結果が `修正` の場合、Critic が何を修正したかを読む

以下に該当するカードは、その日は行動の根拠にしない。

- 弱気論拠が定型的で、具体的な数値や開示への言及がない
- 引用に `原文で確認できません` が含まれる（本来 Critic が却下するので、出ていたら不具合）
- `期待超過リターン` の区間が ±10% を超えて広い（方向性の情報がない）
- 母数が10件未満

### 5. 却下されたものを確認（週1回でよい）

```
/recommendations?critic_verdict=rejected
```

却下率が0%の日が続いていたら、Critic が機能していない疑い。30%を大きく超えていたら Strategist の
プロンプトを見直す。

### 6. 保有銘柄との矛盾

`/portfolio` の `現在の見立て` 列で、保有銘柄に `縮小検討` / `回避` が出ていないか確認する。ここは
意図的に自分のポジションに反対する情報が出る場所なので、無視せず理由を読む。

## 夕方の手順（引け後、目安3分）

### 1. 当日の開示

`/filings?from=today` で保有・ウォッチ銘柄の開示を確認する。業績予想の修正があれば要約を読む。

日本株の15時以降の開示は**翌営業日の推奨に反映される**。当日の推奨には入っていないので、自分で
読む必要がある。

### 2. 売買を記録

その日に売買したものがあれば `/portfolio` から記録する。翌日以降に書くと、心理状態タグと撤退計画が
正確に書けなくなる。これが後の「実行の質」分析の入力になる。

### 3. 翌日のジョブ予定を確認

PC がスリープ設定になっていないか、Windows Update の再起動が予定されていないかを確認する。
確認方法は `verify-windows-runtime` スキル。

## 部分失敗の判断表

| 欠けたもの | 推奨を信用してよいか | 対応 |
| --- | --- | --- |
| TDnet | よい | 適時開示が反映されていないことだけ意識する。既定で無効なら通常状態 |
| EDINET の一部 | 条件付き | その銘柄の推奨だけ定性評価が薄い。カード上に表示される |
| yfinance | **よくない** | 参考価格が古い。価格に基づく判断はしない |
| J-Quants | 条件付き | 12週遅延は正常。それより古い場合はスコアが古い |
| FRED | よい | 為替予測が前日のもの。為替を根拠にした推奨は割り引く |
| LLM（コスト上限） | 条件付き | 定性評価なしの定量スコアのみ。弱気論拠は定量的な要因のみで構成される |
| Analyst 全体 | **よくない** | スコアが更新されていない。前日のスコアで推奨が出ている |
| Critic | **よくない** | 未検証の推奨が出ている。引用の実在性が保証されない |
| Evaluator | よい | 実績評価と教訓更新が遅れるだけ。当日の推奨には影響しない |

`Critic` が失敗した日の推奨は使わない。引用の検証がされていない推奨は、LLM が資料に書かれていない
ことを書いている可能性がある。

## 手動でレポートを生成する場合

エージェントが停止していて、手動で当日分を回す場合:

```bash
# 順序どおりに実行する。依存関係がある
uv run python -m services.agent.run collector_jp --date 2026-08-22
uv run python -m services.agent.run analyst      --date 2026-08-22
uv run python -m services.agent.run researcher   --date 2026-08-22
uv run python -m services.agent.run strategist   --date 2026-08-22
uv run python -m services.agent.run critic       --date 2026-08-22
uv run python -m services.agent.run evaluator    --date 2026-08-22
```

いずれも冪等なので、同じ日付で再実行しても結果は変わらない。ただし `--force` を付けた場合は
LLM コストが再発生する。

`researcher` 以降は LLM を使うため、実行前に当日のコスト残を確認する。

## 週次で確認すること

| 項目 | 場所 | 見るポイント |
| --- | --- | --- |
| 推奨の実績 | `/portfolio?tab=analysis` | 確信度別の的中率が単調か |
| 実行の質 | 同上 | `emotion_tag` 別の的中率。`fomo` が低いのが典型 |
| 教訓の棚卸し | `/agent?tab=memory` | 有害フラグが立った教訓を無効化する |
| Rank IC | `/model-lab` | 直近20営業日が3ヶ月平均から大きく乖離していないか |
| 却下理由の内訳 | `/agent?tab=critic` | 特定の理由が急増していないか |
| コスト | `/agent?tab=cost` | キャッシュヒット率が下がっていないか |

## 月次で確認すること

- バックアップが成功しているか（`/settings#system`）
- `data/` の使用量とディスク空き
- J-Quants を Light プランに上げる価値があるか（12週遅延が実際に判断を妨げているか）
- 月次コストの実績と見込みの乖離
