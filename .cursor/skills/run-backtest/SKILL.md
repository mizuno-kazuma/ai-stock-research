# バックテストの実行と判定

バックテストの目的は「良い戦略を見つけること」ではなく、**その戦略を採用してよいかを却下基準で
判定すること**。良い数字を探し回るほど多重検定バイアスが積み上がり、Deflated Sharpe Ratio が
下がる。試行回数は必ず記録する。

関連仕様: [04-analysis-engine.md](../../../docs/04-analysis-engine.md) §4、
[09-api-spec.md](../../../docs/09-api-spec.md) §2.7、
[ui/screens/07-model-lab.md](../../../docs/ui/screens/07-model-lab.md)

## 手順

### 1. 検証したい仮説を1文で書く

書けないならまだ実行しない。「なんとなく良さそうなパラメータを探す」実行は、そのすべてが
`n_trials` に加算され、後の有意性判定を悪化させる。

良い例: 「予想改定と割安さの組み合わせは、H20 で TOPIX を年率2%以上上回る」
悪い例: 「銘柄数を10から30まで変えて一番良いものを探す」

後者を行う場合は「パラメータ感度の確認」であって有意性の主張には使えない、と明示的に扱う。

### 2. コストパラメータを決める（省略不可）

| パラメータ | 決め方 | 例 |
| --- | --- | --- |
| `fee_bps` | 使う証券会社の実際の手数料率 | 楽天証券の現物で 5.0bp |
| `slippage_bps` | 対象銘柄の流動性から。大型株 10bp、中型株 20bp、小型株 40bp 以上 | 10.0 |
| `max_turnover_pct` | 実際に自分が回せる頻度。月次リバランスで 30% が目安 | 30.0 |

**API とライブラリの両方でデフォルト値を持たせない。** 未指定は 422 エラーにする。デフォルト値が
あると、指定を忘れたバックテストが「コストゼロの結果」として残り、後から判別できなくなる。

米国株のスリッページは日本株より小さく設定してよいが、ゼロにはしない。

### 3. 期間を決める

| 条件 | 理由 |
| --- | --- |
| 最低12ヶ月、できれば24ヶ月以上 | それ未満では DSR がほぼ有意にならない |
| 終了日は今日から20営業日以上前 | H20 のラベルが確定していない期間を含めない |
| 局面を跨ぐこと | 上昇局面だけの検証は意味がない。ドローダウン局面を必ず含める |
| J-Quants 無料プランでは過去2年が上限 | 12週遅延を考慮すると実質的にさらに短い |

無料プランの2年制限は本質的な制約。24ヶ月しか取れない前提で、DSR が有意になりにくいことを
最初から想定しておく。

### 4. 実行

```bash
uv run python -m services.agent.backtest \
  --strategy value_quality_h20 \
  --market JP \
  --period-start 2024-08-01 --period-end 2026-08-01 \
  --rebalance monthly \
  --n-positions 20 \
  --fee-bps 5.0 \
  --slippage-bps 10.0 \
  --max-turnover-pct 30.0 \
  --signal quant_score --weight-set ws_20260701_a \
  --min-adv 100000000 --min-market-cap 30000000000
```

API 経由の場合:

```bash
curl -s -X POST localhost:8000/api/v1/backtests \
  -H 'content-type: application/json' \
  -d '{"strategy_name":"value_quality_h20","market":"JP",
       "period_start":"2024-08-01","period_end":"2026-08-01",
       "rebalance_freq":"monthly","n_positions":20,
       "fee_bps":5.0,"slippage_bps":10.0,"max_turnover_pct":30.0,
       "signal_source":{"type":"quant_score","weight_set_id":"ws_20260701_a"},
       "universe_filter":{"min_adv_20d":100000000,"min_market_cap":30000000000}}'
```

`202 Accepted` と `job_run_id` が返る。進捗は SSE または `GET /api/v1/backtests/{id}`。

### 5. 実行前に確認されること（自動）

実装側で以下を検証し、1つでも満たさなければ実行しない。

- [ ] `fee_bps` / `slippage_bps` / `max_turnover_pct` が指定されている
- [ ] エントリーが翌営業日始値になっている（`T-LEAK-05`）
- [ ] ユニバースが各時点で実在した銘柄のみ（サバイバルバイアス対策）
- [ ] シグナルが `prices_live` を参照していない（`T-LEAK-02`）
- [ ] 期間終了日が現在から20営業日以上前
- [ ] `n_trials` が `backtest_runs` に記録される

### 6. 結果を判定する

`backtest_runs` に記録される値のうち、判定に使うのは以下。

| 指標 | 見るポイント |
| --- | --- |
| `sharpe` | 参考値。単独では判断しない |
| `deflated_sharpe` | **これが判定の主指標** |
| `dsr_p_value` | 0.05 未満で「有意」 |
| `n_trials` | DSR の入力。累積の探索回数 |
| `cost_drag_annual` | コストで失われた年率リターン |
| `gross_annualized_return` | コスト前の年率リターン |
| `realized_turnover_pct` | 上限に張り付いていないか |
| `max_drawdown` | 自分が耐えられる水準か |
| `monthly_hit_rate` | 勝率とサンプル数（月数） |

#### 却下基準（1つでも該当したら採用しない）

| 基準 | 理由 |
| --- | --- |
| `dsr_p_value >= 0.05` | 試行回数を考慮すると偶然と区別できない |
| `cost_drag_annual` が `excess_return` の50%超 | コスト前提が少し悪化するだけで消える |
| `realized_turnover_pct` が上限に張り付いている | 上限が結果を決めており、戦略の性質が測れていない |
| `n_months < 12` | サンプルが足りない |
| ドローダウン期間が検証期間の40%超 | 実際には途中でやめる |
| 上位3銘柄が総リターンの50%超を占める | 少数の当たりに依存しており再現しない |
| `n_trials` が記録されていない | 有意性を判定できないため無効 |

#### 採用してよい場合の扱い

DSR が有意でも、それは「この期間、この市場で有意だった」という意味しかない。本番のファクター
重みに反映する前に:

1. 別の期間（前半・後半に分割）で再現するか
2. 別の市場（JP で見つけたなら US）で符号が一致するか
3. コストを1.5倍にしても超過リターンが残るか

3つとも満たしてから、モデルラボの重み承認フローに載せる。

### 7. 記録する

`backtest_runs` に自動記録されるが、以下は人が書く。

- 検証した仮説（1文）
- 却下したか採用したか、その理由
- パラメータ感度の確認だった場合はその旨（有意性の主張に使わないため）

記録しないと、3ヶ月後に同じ検証を繰り返し、`n_trials` だけが増える。

### 8. UI で確認

`/model-lab?tab=backtests` で結果カードを開き、以下が表示されていることを確認する。

- コスト前提が結果より**先に**表示されている
- DSR と `n_trials` が併記されている
- 有意性の判定文が「統計的に有意とは言えません」を含む場合、それが正しく出ている
- コスト前とコスト後の年率リターンが両方見える

表示が欠けている場合は UI の不具合として直す。コスト前提が見えないバックテスト結果は、後から
見返したときに解釈できない。

## Deflated Sharpe Ratio の解釈

DSR は「これだけ試行したうえで、この程度のシャープレシオが偶然出る確率」を補正した指標。

| 状況 | Sharpe | n_trials | DSR | 解釈 |
| --- | --- | --- | --- | --- |
| 1回で出した | 0.62 | 1 | 0.55 | ほぼそのまま |
| 120回試した | 0.62 | 120 | 0.18 | 偶然の範囲 |
| 120回試した | 0.82 | 120 | 0.71 | 試行を考慮しても有意 |
| 1000回試した | 0.82 | 1000 | 0.31 | 有意でなくなる |

つまり**探索を増やすほど、同じシャープレシオの価値は下がる**。これは統計的に正しく、直感に反する
が受け入れる必要がある。パラメータをたくさん試すこと自体がコストを持つ。

歪度と尖度も DSR の入力になる。リターン分布が左に歪んでいる（大きな損失が稀に出る）戦略は、
同じシャープレシオでも DSR が下がる。

## よくある失敗

| 失敗 | 症状 | 対策 |
| --- | --- | --- |
| コストを省略した | 年率+15%などの非現実的な成績 | 必須引数化、`T-LEAK-06` |
| 当日終値でエントリー | 実運用で再現しない | 翌営業日始値、`T-LEAK-05` |
| 現在の上場銘柄だけで検証 | 成績が過大 | `valid_from` / `valid_to` を使う |
| `n_trials` を1のまま放置 | DSR が実態より良く出る | 累積の探索回数を記録 |
| 良かった結果だけを残す | 判断が歪む | 却下した結果も残す |
| 回転率上限が緩すぎる | 月100%回転など実行不可能な戦略 | 自分が実際に回せる水準にする |
| 期間終了日が直近 | H20 ラベル未確定分が含まれる | 20営業日以上前で終える |
