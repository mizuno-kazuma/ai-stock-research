# エージェント評価ループのレビュー

Evaluator が自動で回すループを、人が定期的に点検する手順。フィードバックループは放置すると
劣化する。少数サンプルから抽出した教訓が後続の推奨を継続的に悪化させるのが典型的な失敗で、
それを検出できるのは人が数字を見たときだけ。

関連仕様: [08-agent-loop.md](../../../docs/08-agent-loop.md) §7、
[05-scoring-screening.md](../../../docs/05-scoring-screening.md) §8、
[ui/screens/08-agent-console.md](../../../docs/ui/screens/08-agent-console.md)

## Evaluator が自動で行うこと

人が介入する前に、何が自動化されているかを把握しておく。

| 処理 | 内容 |
| --- | --- |
| 実績確定 | 生成の翌営業日始値をエントリー価格とし、H5 / H20 後の超過リターンを計算 |
| MFE / MAE | 保有期間中の最大含み益・最大含み損を記録 |
| 集計 | 確信度別・reason code 別・セクター別・ホライズン別の的中率 |
| 教訓の候補生成 | 統計的に差が出た条件を LLM で言語化して `agent_memory` に提案 |
| 重みの再フィット | Ridge 回帰（非負制約）で `factor_weights` を提案（適用はしない） |

**重みの適用は自動では行わない。** 承認制が既定。

## 手順

### 1. 実績が正しく確定しているか確認

```bash
curl -s localhost:8000/api/v1/trades/analysis | jq '.data.recommendation_quality'
```

確認点:

- `n_recommendations` が想定どおり増えているか（1日12件 x 営業日数）
- `判定前` の件数が H20 なら直近20営業日分に収まっているか
- エントリー価格が翌営業日始値になっているか（当日終値だと `T-LEAK-05` 違反）

運用初期は判定済みが少ない。運用開始から20営業日未満なら、H20 の実績はゼロ件で正常。

### 2. 確信度の単調性を検証（最重要）

```
高 61% (n=42) > 中 56% (n=98) > 低 51% (n=74)
```

この順序が崩れていたら、確信度の付け方に問題がある。確信度は UI 上で最も強く行動を左右する
表示なので、単調でない確信度は害になる。

| 状態 | 判断 | 対応 |
| --- | --- | --- |
| 単調で差が5ポイント以上 | 正常 | そのまま |
| 単調だが差が2ポイント未満 | 確信度がほぼ意味を持っていない | 確信度の算出ロジックを見直す |
| 単調でない | 問題あり | `conviction_score` の入力（母数、区間幅、モデル成績）を確認 |
| すべて同一値 | 運用初期で母数不足のため `低` 固定 | **不具合ではない**。母数が増えるまで正常な挙動 |

最後のケースは誤認しやすい。`n_prior_samples < 20` で `低` を強制する仕様のため、運用開始直後は
すべて `低` になる。

### 3. reason code 別の実績を確認

```bash
curl -s 'localhost:8000/api/v1/agent/critic-stats?days=90' | jq '.data'
```

的中率が明確に低い reason code があれば、そのファクターの寄与を見直す候補になる。ただし
**単独の reason code の的中率でファクター重みを手で変えない**。重み変更は Ridge の提案経路に
乗せる。手で触ると多重検定バイアスが積み上がる。

### 4. 教訓を棚卸しする

`/agent?tab=memory` を開く。以下の基準で判断する。

#### 有害な教訓を無効化する

「効果」欄で、その教訓を使用した推奨の的中率が未使用より**5ポイント以上低く、かつ使用側の
サンプルが20件以上**あるものは無効化する。

```
「低ボラ銘柄を優先する」
  使用時 44% (n=32) / 未使用 56% (n=112)   → 無効化
```

サンプルが20件未満の場合は無効化せず、観察を続ける。少ないサンプルで無効化すると、今度は
無効化の判断自体がノイズになる。

#### 曖昧な教訓を無効化する

具体的な条件・数値・母数を含まない教訓は、プロンプトに注入しても出力を改善せず、トークンを
消費するだけ。

```
悪い: 「割高な銘柄には注意する」            → 無効化（条件が特定できない）
良い: 「予想PERが過去5年上限圏かつ予想改定が下向きの銘柄は的中率41% (n=34)」
```

#### 重複を統合する

同じ内容の教訓が複数あると、プロンプト内で同じ主張が繰り返され、LLM がその点を過大に重視する。
1つに統合し、根拠のサンプル数を合算する。

#### 古い教訓を見直す

`updated_at` が6ヶ月以上前で、直近30日の注入回数が0の教訓は、条件に合致する銘柄が出ていない。
無効化してよい。

#### 上限

有効な教訓は**20件程度を上限**とする。それ以上になるとプロンプトが長くなり、コストが増え、
個々の教訓の影響が薄まる。上限に達したら、効果の小さいものから無効化する。

### 5. 教訓を追加する場合の基準

自動生成されたものを承認する場合も、手で追加する場合も同じ基準を適用する。

| 条件 | 必須 |
| --- | --- |
| 根拠となるサンプル数が30件以上 | 必須 |
| 具体的な条件（数値・期間・ファクター名）を含む | 必須 |
| 的中率の差が5ポイント以上 | 必須 |
| 差が偶然でない（二項検定で p < 0.10 程度） | 望ましい |
| 適用範囲（global / market / sector / ticker）が明示されている | 必須 |
| 経済的に説明できる | 望ましい |

最後の項目を満たさない教訓は、過去データへの当てはめである可能性が高い。追加してもよいが、
`category: pattern` として、効果が出ない場合は早めに無効化する。

### 6. ファクター重みの提案を判断する

`/model-lab?tab=weights` で提案内容を確認する。

```
                現在    提案    変化
バリュエーション  0.22    0.26   +0.04
クオリティ        0.18    0.16   -0.02
モメンタム        0.20    0.16   -0.04
成長              0.12    0.10   -0.02
予想改定          0.20    0.26   +0.06
ボラティリティ    0.04    0.03   -0.01
流動性            0.04    0.03   -0.01

推定の根拠: Ridge回帰（非負制約）· 対象 214件 · 2026年2月 - 2026年8月 · 現行と50%ブレンド
```

#### 承認する条件

- [ ] 推定に使ったサンプルが100件以上
- [ ] 個々の重みの変化が ±0.10 以内（急激な変化は過剰適合の兆候）
- [ ] 非負制約が効いている（負の重みが出ていない）
- [ ] 現行重みとのブレンド率が50%程度（提案をそのまま採用しない）
- [ ] 変化の方向が直近の実績と整合している
- [ ] 直近3回の提案で同じ方向の変化が続いていない（振動していないか、逆に一方向に暴走していないか）

#### 承認しない場合

サンプル不足、変化が大きすぎる、または直近の重み変更から1ヶ月経っていない場合は却下する。重みを
頻繁に変えると、変更の効果を測る期間が確保できない。**最低1ヶ月は同じ重みで運用する。**

却下は理由を記録して行う。記録しないと、翌月に同じ提案を同じ理由で却下することになる。

### 7. 重み変更後の追跡

承認したら、次の1ヶ月は以下を追跡する。

- Rank IC が変更前より悪化していないか
- 推奨されるセクターの偏りが増えていないか
- 却下率が上がっていないか（重みが偏ると Critic が引っかかる推奨が増える）

悪化していたら前の重みセットに戻す。`factor_weights` の履歴は残っているので戻せる。

### 8. 「推奨の質」と「実行の質」を分けて読む

`/portfolio?tab=analysis` の2つのパネルは目的が違う。混ぜて読むと改善対象を間違える。

| パネル | 対象 | 改善方法 |
| --- | --- | --- |
| 推奨の質 | 全推奨（売買したかに関係なく） | ファクター、モデル、教訓の改善 |
| 実行の質 | 実際の売買のみ | 自分の行動の変更 |

経験的に、実行の質の方が改善余地が大きいことが多い。`emotion_tag` 別の的中率で `fomo` が
著しく低い場合、モデルをいくら改善しても効果が薄い。この場合の対策はコードではなく、
「`fomo` タグを付けたくなったら記録だけして翌日まで待つ」という運用ルール。

## 運用初期（開始から3ヶ月未満）の扱い

以下は不具合ではなく仕様どおりの挙動。誤認しないこと。

| 現象 | 理由 |
| --- | --- |
| 確信度がすべて `低` | `n_prior_samples < 20` で強制される |
| 的中率が `—` と表示される | 母数が不足しており表示しない |
| 教訓が0件 | 実績が確定していない |
| 重みの提案が出ない | サンプルが100件未満 |
| 「類似条件の過去実績」が空 | 同上 |

この期間は、ループの点検ではなく**データが正しく蓄積されているか**を確認する。
`recommendation_outcomes` に行が増えているか、エントリー価格が翌営業日始値になっているかを見る。

## チェックリスト（週次）

- [ ] 確信度の単調性が保たれている
- [ ] 有害フラグが立った教訓がない、または無効化した
- [ ] 有効な教訓が20件以内
- [ ] 却下率が5% - 30% の範囲にある
- [ ] 重みの提案があれば承認基準に照らして判断した
- [ ] `emotion_tag` 別の的中率を確認した

## チェックリスト（月次）

- [ ] 教訓の全件を読み、曖昧なもの・古いものを整理した
- [ ] 重み変更後の Rank IC を変更前と比較した
- [ ] 推奨の質と実行の質のどちらに改善余地があるか判断した
- [ ] 3ヶ月以上効果が確認できない教訓を無効化した
