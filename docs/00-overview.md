# 00. 概要・スコープ・非機能要件

## 1. このツールの目的

日米株式（東証上場銘柄および米国上場銘柄）について、公開情報を自動収集・構造化し、統計分析とLLMによる定性分析を組み合わせて**売買判断の材料を提示する**個人用ツールである。

判断の主体は常に人間（利用者本人）であり、本ツールは以下を提供する。

1. 毎日決まった時刻に更新される、根拠付きの注目銘柄リスト
2. 銘柄ごとの定量スコア（ファクター合成）と定性所見（LLMによる開示資料読解）
3. 決算資料・適時開示への**ワンクリック到達**（探す時間をゼロにする）
4. 為替（USD/JPY）とマクロ指標の見通し、および信頼区間
5. 過去の推奨と実績を突き合わせた自己評価履歴（当たっていないことも含めて可視化する）
6. スマートフォンからの閲覧（PWA）

## 2. スコープ

### 2.1 スコープに含む（Phase A / B）

| 領域 | 内容 |
| --- | --- |
| データ収集 | J-Quants API、EDINET API v2、TDnet、yfinance、SEC EDGAR、FRED API |
| 保存 | 生レスポンスのParquet保存、DuckDBによる分析用テーブル、SQLiteによる状態管理 |
| 分析 | ファクター計算、GARCHボラ推定、ARIMAX/VECMによる為替予測、LightGBMによるクロスセクショナル・ランキング |
| 検証 | Purged Walk-Forward CV、Diebold-Mariano検定、Deflated Sharpe Ratio、バックテスト（手数料・スリッページ込み） |
| LLM | 開示資料の要約・リスク抽出・定性スコア、RAGによる根拠提示 |
| エージェント | 6ジョブの日次ループ（Collector / Analyst / Researcher / Strategist / Critic / Evaluator） |
| UI | Next.js製のWeb UI（PWA）、10画面 |
| 配信 | WSL2上で稼働し、Tailscale経由でスマートフォンから利用（Phase A） |
| 記録 | 手動売買の記録（売買日誌）、ポートフォリオの評価損益表示 |

### 2.2 スコープに含まない（明示的な非スコープ）

| 項目 | 理由・扱い |
| --- | --- |
| **自動発注・自動売買** | 本バージョンでは実装しない。判断支援のみ。将来拡張として [14-future-brokerage.md](14-future-brokerage.md) に設計と比較のみを記載し、`ExecutionAdapter` インターフェースだけを先行定義する |
| 証券口座との残高自動連携 | ポートフォリオは手入力またはCSVインポート |
| 板情報・ティックデータ・HFT的な短期売買 | 日足ベース。ホライズンは5営業日および20営業日 |
| デリバティブ（オプション・先物）の評価 | 対象外 |
| 他人への情報提供・投資助言 | 個人利用限定。金商法上の投資助言業に該当する行為は行わない |
| マルチユーザー・課金・SaaS化 | 単一利用者前提 |
| オンプレLLMの常用 | クラウドAPIを使う。ローカルLLMは検討外（Phase Bでのコスト最適化時に再検討の余地のみ残す） |

### 2.3 前提となる利用者像

- 個人投資家1名。日本在住、日本語話者
- 平日の限られた時間（朝と夜）に確認する
- Windows 11 PC（常時稼働可能）と、iOS/Android スマートフォンを持つ
- Python / TypeScript のコードを読める。ただし運用に手間はかけたくない

## 3. 非機能要件

### 3.1 性能

| 指標 | 目標値 | 備考 |
| --- | --- | --- |
| 日次バッチ全体の所要時間 | 60分以内 | J-Quants無料プランの 5 req/min が支配的なボトルネック |
| API応答（キャッシュヒット時） | p95 300ms 以内 | DuckDB経由の集計クエリ |
| API応答（キャッシュミス時） | p95 3s 以内 | 重い集計は事前計算テーブルへ退避する |
| 初回ページロード（モバイル、Tailscale経由） | LCP 2.5s 以内 | 3G相当ではなくTailscale経由のWi-Fi/4Gを想定 |
| 銘柄詳細のチャート描画 | 500ms 以内 | 直近2年の日足（約490本）を前提 |
| 対象銘柄数 | 日本株 約4,000銘柄 + 米国株 約1,000銘柄 | 米国は主要指数構成銘柄に絞る |

### 3.2 可用性・耐障害性

- **単一障害点の許容**: 個人用なので冗長構成は取らない。ただし「壊れたことがすぐ分かる」ことを重視する
- **PCのスリープ・Windows Updateによる再起動を前提に設計する**。全ジョブは冪等であり、チェックポイントから再開できること（詳細は [15-windows-runtime.md](15-windows-runtime.md)）
- **機能縮退（graceful degradation）を必須とする**。あるデータソースが落ちても、他のソースで得られる範囲の結果を返す。UIには「このセクションはデータ取得に失敗している」旨を明示する（partial-data 状態）
- リトライは指数バックオフ（初回4秒、最大5回）。恒久的に失敗した場合は `job_runs` テーブルに記録し、翌日のバッチで再試行する

### 3.3 データ品質・再現性

- **生レスポンスを必ず保存する**。正規化ロジックにバグが見つかったとき、APIを再度叩かずに再構築できるようにする（無料枠のレート制限下ではこれが決定的に重要）
- すべての分析結果に `as_of`（データ基準日）と `computed_at`（計算時刻）を持たせる
- **データ鮮度をUIに常時表示する**。J-Quants無料プランは12週遅延であり、これを隠すと致命的な誤判断につながる
- モデルの学習・推論には `run_id` を振り、入力データのスナップショットハッシュを記録する

### 3.4 統計的誠実性（本プロジェクトの第一級要件）

これは「あったら良い」要件ではなく、**設計上の必須制約**として扱う。詳細は [04-analysis-engine.md](04-analysis-engine.md) および [12-testing-validation.md](12-testing-validation.md)。

| 原則 | 具体的な強制方法 |
| --- | --- |
| 予測は当たらない前提で作る | すべての予測値に信頼区間と過去の的中率を併記する。点推定のみの表示をUIレベルで禁止する |
| ベースラインに勝てないモデルは採用しない | 為替はランダムウォークをベースラインとし、Diebold-Mariano検定で有意差を確認できないモデルは「優位性なし」と表示する |
| リークを構造的に防ぐ | 株価ランキングは Purged Walk-Forward CV + embargo のみを許可する。単純なKFoldはコードレベルで使わせない |
| 多重検定バイアスを開示する | バックテスト結果には試行回数を記録し、Deflated Sharpe Ratio を必ず出力する |
| 取引コストを無視しない | バックテストAPIは手数料・スリッページ・売買回転率上限を**必須引数**とする（デフォルト値を持たせない） |
| LLMの出力を鵜呑みにしない | すべてのLLM出力に引用（ドキュメントIDと該当箇所）を必須化し、Criticジョブが引用の実在性を検証する |
| 強気論拠だけを見せない | 推奨カードには**必ず弱気論拠（bear case）を含める**。bear case が空の推奨は生成できない |

### 3.5 コスト

| 項目 | 目標 |
| --- | --- |
| データソース費用 | 0円で開始（全て無料枠）。J-Quants Light（月1,650円）への移行は設定変更のみで可能にする |
| LLM費用 | 月 $5-15。日次コストキャップとキルスイッチを実装（[11-security-ops.md](11-security-ops.md)） |
| インフラ費用 | Phase A は 0円（自宅PC + Tailscale無料プラン） |

### 3.6 セキュリティ

- APIキーはコードにもGitにも含めない。`.env`（gitignore済み）と環境変数のみ
- Tailscale の tailnet 内からのみアクセス可能。インターネットへの直接公開はしない
- Phase B でクラウド移行する場合は認証（単一ユーザー向けのパスキーまたはOIDC）を追加する
- LLMプロバイダに送るデータは公開情報のみ。保有ポジションや資産額はプロンプトに含めない（`redact` フィルタを通す）

### 3.7 移植性

- Phase A（自宅PC）から Phase B（クラウド）への移行が**書き換えではなく設定変更**で済むこと
  - SQLite → PostgreSQL: SQLAlchemy 経由なので接続文字列の変更のみ
  - LanceDB → pgvector: `VectorStore` 抽象の実装差し替えのみ
  - APScheduler: そのまま動く（OS依存のcron / タスクスケジューラを使わない理由）
  - LLM: LiteLLM 経由なのでモデル識別子は1ファイルに集約

## 4. 主要な設計判断（Decision Log）

| ID | 決定 | 理由 | 却下した代替案 |
| --- | --- | --- | --- |
| D-01 | 発注機能を持たない | 誤発注のリスクが、得られる利便性に対して大きすぎる。まず判断支援の精度を上げる | 最初から自動発注を組み込む |
| D-02 | J-Quants 無料プラン（12週遅延）で開始 | 学習・バックテストには十分。遅延ギャップは yfinance で補完できる | 最初から Light プラン課金 |
| D-03 | リサーチ用価格と執行時価格を別モジュールにする | 12週遅延データと当日データを同じ経路で扱うと、遅延データで現在値を表示する事故が起きる | 単一の価格テーブルに混在させる |
| D-04 | スケジューラをアプリ内（APScheduler）に持つ | cron / Windows タスクスケジューラはOS依存で、Phase B移行時に作り直しになる。WSL2の起動タイミング問題も回避できる | cron、Windows タスクスケジューラ |
| D-05 | LLMをLiteLLM経由で呼ぶ | モデル名と価格が頻繁に変わる。識別子を1ファイルに集約し、アプリコードから排除する | 各プロバイダのSDKを直接呼ぶ |
| D-06 | Tailscale は Windows ホストのみに入れる | WSL2内にも入れると二重カプセル化でMTU不足になり通信が壊れる（Tailscale公式が非推奨） | WSL2内にTailscaleを入れる |
| D-07 | ストレージは DuckDB + Parquet / SQLite の二本立て | 分析クエリ（列指向・スキャン中心）と状態管理（行指向・更新中心）の要求が正反対 | 全部SQLite、または全部DuckDB |
| D-08 | UIはPWA（ネイティブアプリを作らない） | 単一コードベースで済み、Phase Bのクラウド移行後もそのまま使える | React Native / Flutter |
| D-09 | Figma Make向けドキュメントの構造説明を英語で書く | 生成品質が明確に高い。ただし画面内の実テキストは日本語で併記する | 全部日本語 |
| D-10 | 上昇・下落の色を設定で切り替え可能にする | 日本式（赤=上昇）と米国式（緑=上昇）が真逆であり、両市場を扱うため固定できない | どちらかに固定 |

## 5. 用語集

| 用語 | 定義 |
| --- | --- |
| as_of | データの基準日。「いつ時点の情報か」を示す |
| computed_at | 分析・推論が実行された時刻 |
| ホライズン (horizon) | 予測の対象期間。本ツールでは 5営業日（H5）と 20営業日（H20） |
| ファクター (factor) | 銘柄の特徴を表す数値。バリュー、モメンタム、クオリティ、成長、ボラティリティなど |
| セクター中立化 | 業種内でz-scoreを取り直し、業種要因を除去すること |
| 定量スコア | ファクターの重み付き合成値。0-100に正規化して表示 |
| 定性スコア | LLMが開示資料を読んで付与するスコア。定量スコアへのオーバーレイとして機能する |
| reason code | 推奨理由を機械可読な短いコードで表したもの（例: `VAL_CHEAP_VS_SECTOR`, `MOM_20D_POSITIVE`） |
| bear case | 弱気論拠。その推奨が外れるシナリオと、その根拠 |
| Purged Walk-Forward CV | 時系列の順序を保った交差検証。学習期間と検証期間の間にラベル期間分の除外（purge）と余白（embargo）を挿入し、リークを防ぐ |
| embargo | purge に加えて設ける追加の待機期間。系列相関によるリークを抑える |
| Deflated Sharpe Ratio (DSR) | 試行回数を考慮して調整したシャープレシオ。多重検定バイアスの度合いを示す |
| Diebold-Mariano検定 (DM検定) | 2つの予測モデルの予測誤差に統計的有意差があるかを検定する手法 |
| PIT (Point-in-Time) | ある時点で実際に入手可能だった情報のみを使うこと。財務データの遡及修正によるリークを防ぐ |
| agent_memory | Evaluatorが蓄積する教訓ストア。以降のプロンプトに注入され、フィードバックループの実体となる |
| 機能縮退 | 一部のデータソースが失敗しても、得られた範囲で結果を返す動作 |
| J-Quants | JPX（日本取引所グループ）公式の株式データAPI |
| EDINET | 金融庁の有価証券報告書等の電子開示システム |
| TDnet | 東証の適時開示情報閲覧サービス |
| EDGAR | 米国SECの企業開示システム |
| FRED | セントルイス連銀の経済統計データベース |
| tailnet | Tailscale が構成するプライベートネットワーク |
| mirrored networking | WSL2 のネットワークモード。Windows ホストのネットワークインターフェースをWSL2に鏡像化する |
